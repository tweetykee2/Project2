# 캐릭터 디자인 시트

캐릭터 하나를 여러 장면, 여러 AI 도구에서 **똑같이** 그릴 수 있도록 규칙을 정리하고, 디자인 시트 이미지를 만드는 프롬프트를 쓴다.
대화는 사용자의 언어로 하고, 이미지 프롬프트 본문은 영어로 쓴다.

## 1단계: 자료 확인

- **참고 이미지가 있으면** 먼저 꼼꼼히 관찰한다. 실루엣, 머리 모양, 옷 주름과 끈, 신발, 소품, 선 굵기, 명암 방식(평면/스크린톤/그라데이션), 배경색, 강조색을 확인한다.
- 저장소에 `characters/<이름>.md`가 이미 있으면 읽고, 그 내용을 기준으로 이어서 작업한다.
- 이미지가 여러 장이고 서로 다르면(예: 바지 색, 소품 유무, 명암 방식) **추측으로 합치지 말고** 차이를 표로 보여 준 뒤 어느 쪽이 기준인지 묻는다. 둘 다 맞다면 "의상 버전"으로 나눈다.
- 빠진 정보만 한 번에 묻는다: 작품 제목·세계관, 캐릭터 성격 한 줄, 필요한 상태(예: 후드 ON/OFF, 변신 전후), 필요한 표정, 쓸 AI 도구.

## 2단계: 캐릭터 바이블 쓰기

`template.md` 형식을 따라 채운다. 핵심 원칙:

1. **고정 토큰(Character token)**: 영어 한 문단(40~70단어). 모든 프롬프트에 **글자 하나 바꾸지 않고** 붙여 넣는 문장이다. 실루엣 → 머리·얼굴 → 상의 → 하의 → 신발 → 소품 → 그림체 순서로 쓴다.
2. **시그니처 요소**: 이 캐릭터를 알아보게 만드는 것 3~5개. 예: 초록 브릿지 머리, 커다란 흰 후드, 어둠 속 초록 눈. 이것이 빠지면 다른 캐릭터가 된다.
3. **절대 하지 말 것**: AI가 자주 틀리는 부분을 미리 막는다. 예: 후드 ON일 때 얼굴 이목구비를 그리지 않는다, 브릿지 색을 바꾸지 않는다, 바지에 무늬를 넣지 않는다.
4. **팔레트**: HEX 코드와 각 색이 어디에 쓰이는지. 참고 이미지에 HEX가 있으면 그대로 쓰고, 없으면 이미지에서 추정해 "추정"이라고 표시한다.
5. **상태·의상 버전**: 각 버전마다 고정 토큰에서 **무엇이 바뀌는지만** 적는다(차이 토큰).
6. **표정 세트**: 표정 이름, 짧은 설명, 그리는 법(눈·눈썹·입). 상태마다 표정 표현 방식이 다르면(예: 눈만으로 표현) 따로 적는다.
7. **그림체 토큰**: 선 굵기, 명암, 배경, 색 사용 규칙. 예: `bold clean black outlines, flat white fills, halftone dot shading, limited palette, off-white background`.

## 3단계: 디자인 시트 프롬프트

다음 패널마다 프롬프트를 쓴다. 모든 프롬프트는 **고정 토큰 + (버전 차이 토큰) + 패널 내용 + 그림체 토큰** 순서다.

| 패널 | 내용 |
| --- | --- |
| A. 턴어라운드 | `character turnaround sheet, front view, three-quarter view, side view, back view, same pose, full body, evenly spaced, neutral standing pose, plain background` |
| B. 상태·버전 비교 | 버전마다 전신 한 컷, 같은 자세로 나란히 |
| C. 변신·전환 순서 | 상태가 바뀌는 과정 4컷 (예: 후드 벗는 순간 1~4) |
| D. 표정 시트 | `expression sheet, head and shoulders, grid of N expressions` + 표정마다 짧은 설명. 상태별로 따로 만든다 |
| E. 소품·디테일 | 신발, 소품, 머리 장식 확대 |
| F. 한 장 전체 시트 | A~E를 한 장에 배치한 `character design sheet, model sheet layout` 프롬프트. 제목·라벨 글자는 AI가 틀리기 쉬우니 `no text`로 만들고 글자는 나중에 넣으라고 안내한다 |

도구별 형식은 `storyboard-prompt-builder` 스킬의 4단계 규칙을 따른다. Midjourney는 `--ar` 를 패널에 맞게(턴어라운드 3:1 또는 16:9, 표정 시트 1:1, 전체 시트 4:3) 붙인다. 참고 이미지를 넣을 수 있는 도구면 "참고 이미지를 같이 넣으세요"라고 안내한다(예: Midjourney `--cref`, 다른 도구의 reference/이미지 프롬프트 기능).

## 4단계: 결과 보여 주기와 저장

1. 캐릭터 바이블 (`template.md` 형식)
2. 패널별 프롬프트 (복사하기 쉽게 코드 블록)
3. 일관성 체크리스트: 생성된 이미지를 볼 때 확인할 시그니처 요소 목록

그다음 저장을 제안한다. 사용자가 원하면 `characters/<영문-이름>.md`로 저장한다.
**저장소가 공개(public)이면** 저장 전에 "공개 저장소라 누구나 볼 수 있다"고 알리고 확인받는다. 참고 이미지를 저장소에 넣을 때도 마찬가지다.

저장된 캐릭터는 `storyboard-prompt-builder` 스킬이 자동으로 읽어 고정 토큰을 그대로 쓴다. 웹앱(`index.html`)의 캐릭터 칸에는 이름과 고정 토큰을 넣으면 된다.
